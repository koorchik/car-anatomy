# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проєкт

«Анатомія авто»: статичний сайт на GitHub Pages, інтерактивна база знань про будову автомобіля. Поки реалізовано лише розділ про двигуни: 3D-моделі, які можна крутити, заводити й слухати, і конструктор власного двигуна (`#/designer`). Коробки передач і підвіски заплановані, у меню `src/main.ts` вони лише підписані.

Текст, який бачить користувач, пишемо українською. Код, ідентифікатори й коментарі пишемо англійською.

## Команди

```sh
npm run dev                # Vite, http://localhost:5173
npm run build              # tsc --noEmit + vite build у dist/
npm test                   # усі тести vitest
npx tsc --noEmit           # перевірка типів; окремого лінтера немає

npx vitest run tests/synth.test.ts            # один файл
npx vitest run tests/rotary.test.ts -t "apexes"   # один тест за назвою

node scripts/calibrate.ts                     # перегенерувати src/audio/loudness-trim.ts
npm run render-audio [id...]                  # WAV у .tmp/audio і таблиця гучності
node scripts/orders.ts <id> [об/хв] [газ]     # рівень кожного порядку обертів
node scripts/designer-table.ts                # модель конструктора проти заводських цифр
```

`tests/synth.test.ts` рендерить звук офлайн для кожного двигуна, тому це найповільніший файл.

Скрипти виконує сам Node, без збирача, через вбудоване зняття типів (Node ≥ 22.18). Тому імпорти пишемо з розширенням `.ts`, а синтаксис має лише стиратися (`erasableSyntaxOnly`): без `enum` і без параметрів-властивостей у конструкторах.

Деплой робить `.github/workflows/pages.yml` на push у `main`. База Vite відносна (`./`), а маршрути живуть у `#/engines/<id>`, тому сайт працює з будь-якого шляху Pages.

## Архітектура

Двигун описано даними в `src/data/engines.ts` (тип `EngineSpec` у `src/engine/spec.ts`). Решта виводиться з цього опису через `buildEngine()` у `src/engine/kinematics.ts`, а 3D, звук і графіки споживають отриманий `Engine`.

### Кути шийок колінвала виводяться, а не задаються

У даних є порядок запалювання, інтервали й кути рядів. Кут шийки рахується як `pin = alpha - fire`. Тому помилка в порядку запалювання або в нумерації циліндрів (`numbering`, знак `bankA`/`bankB`) дає нереальний колінвал, а не помилку виконання. Це ловлять тести `tests/kinematics.test.ts`: вони перевіряють, що виходять відомі конструкції (хрестовий V8, спільні шийки V12 тощо). Шатуни сидять на спільній шийці лише тоді, коли обчислені кути збіглися (`buildThrows`).

Умовності координат описано на початку `kinematics.ts`: вісь колінвала Z, перед двигуна +Z, кути за годинниковою стрілкою від +Y, якщо дивитись спереду.

### Роторні двигуни йдуть тим самим шляхом

Кожна грань ротора подається як окремий «циліндр» із циклом 1080° (`Engine.cycle`), а `bank` тут означає номер ротора. Тому діаграма циклу, такти й синтез звуку працюють без окремих гілок. Окремі лише `RotaryEngineModel` і `buildRotary`. Поля `bore` і `stroke` у таких двигунів не описують геометрію, вона задається через `R`, `e`, `width`.

### Кут колінвала живе на аудіопотоці

`EngineSim` (`src/engine/sim.ts`) і `EngineSynth` (`src/audio/synth.ts`) виконуються в AudioWorklet, коли звук увімкнено. `Drive` (`src/audio/drive.ts`) на головному потоці отримує звіти, плавно підтягує показаний кут і запускає власну копію `EngineSim`, поки звуку немає.

Звідси обмеження: `src/engine/*`, `src/audio/synth.ts` і `dsp.ts` не можуть торкатися DOM або Web Audio. Цей самий код виконують `scripts/` і тести в Node. Воркет підключено через `worklet.ts?worker&url`.

Режими швидкості в `src/main.ts`:
- «Реально» показує кут із симуляції.
- «Повільно» фіксує оберти через `lockedRpm`, тому рух і звук збігаються.
- «Наочно» крутить модель за окремим кутом `visualTheta`, тому там рух не збігається зі звуком навмисно.

### Звук

Записів немає. Ланцюг такий: імпульс при відкритті випускного клапана → первинна труба → колектор групи → середня труба → глушник → зріз. Окремо додаються впуск, резонанси блока, турбіна й стартер.

Характер двигуна задають не окремі гілки коду, а `exhaust` у даних: які циліндри сходяться в одну групу (`groups`), панорама групи (`pans`) і довжини труб (`headerM`). Бурчання хрестового V8 виникає через нерівні інтервали в групі, а бурчання Subaru через різну довжину труб.

Після зміни `synth.ts` або параметрів `exhaust` запускай `node scripts/calibrate.ts`. Він переписує `src/audio/loudness-trim.ts`, вручну цей файл не редагуємо.

Звук не можна оцінити на слух, тому перевіряємо його вимірюваннями: `scripts/orders.ts` і спектрограмою WAV-файлу через ffmpeg (`showspectrumpic`). Очікувані значення в `tests/synth.test.ts` виведено з фізики, наприклад фазорна сума імпульсів одного ряду. Якщо тест падає, спершу перевір, чи коректна сама фізична вимога, а не підганяй число під код.

### 3D

Обидві моделі реалізують `EngineModel` (`src/scene/model-types.ts`). Геометрія повністю параметрична, зовнішніх 3D-файлів немає (1 одиниця сцени = 100 мм, `MM` у `geometry.ts`).

Як деталі реагують на вигляд задається списками в `PistonEngineModel`:
- `shellMeshes` міняють суцільний матеріал на скляний.
- `peripheral` ховаються у вигляді «Механізм».
- `solidOnly` видно лише у вигляді «Двигун».

Клапани, пружини й штовхачі зроблено через `InstancedMesh` на всі ряди, тому вони не можуть бути в `explodables`. Їхнє зміщення при розбиранні рахується в `updateValves` і має збігатися з напрямком головок у `buildHeads` (множник `2.6`).

Клік по деталі працює через `tag(mesh, 'key')` і словник `src/scene/parts-info.ts`.

### Сили балансування

`BalanceForces` (`src/engine/balance-forces.ts`) кладе кожну силу інерції в точку, де вона діє: обидва порядки поршня, обертову масу кожного шатуна, противагу на кожній щоці, вантажі балансирних валів і ротори. Сили зберігаються на одиницю ω², тому довжина стрілок не залежить від обертів, а ньютони дає `atRpm`. Сума стрілок дорівнює залишку `vibrationTable` з протилежним знаком: там прискорення, тут сила. Цю рівність для кожного двигуна перевіряє `tests/balance-forces.test.ts`, тому після змін у кінематиці чи противагах вона має лишатися точною.

Стрілки малює `BalanceOverlay` (`src/scene/balance-arrows.ts`) у рамці моделі `mounted`, поверх усього. Їхні геометрії мають порожні bounding box, а `raycast` вимкнено, тому кадрування й вибір деталей їх не бачать. Масштаб один на сторінку (`arrowScale`), як і `pageFrameScale`. Маси в `tuning` (`reciprocatingKg`, `rotatingKg`, `rotorKg`) приходять із моделі конструктора й є оцінками. Усі прямі стрілки двигуна йдуть двома `InstancedMesh` (стрижні й наконечники), бо з окремим мешем на стрілку W16 отримував на половину більше draw call.

Маси й відсічка не входять у `geometryKey` конструктора: модель від них не змінюється, тому `DesignerPage` передає такий двигун через `sameShape`, і `BalancePanel.updateEngine` перебудовує лише стрілки або цифри. Каталог поки не знає про заводські балансирні вали (`balanceShafts` у ньому 0), тому текст статті й картки каже «після противаг колінвала», а не «на опори двигуна».

### Конструктор

`Design` (`src/designer/design.ts`) проходить такий шлях: `resolveDesign` → `evaluate` → `designToSpec` → `buildEngine`. Отже, 3D і звук бачать звичайний `EngineSpec`, спільний для каталогу і конструктора. Таблиця моменту `torqueTable` з'являється лише після першої зміни, а на заводській калібровці `EngineSim` працює на вбудованій кривій.

Два рівні обмежень, їх не слід плутати:
- **Геометрія** (`constraints.ts`): межа залежить від інших параметрів (`paramRange`), а `resolveDesign` підсуває залежні значення. Він же обробляє дизайн із чужого посилання, тому кожне нове поле має там перевірятись. Функція має лишатися ідемпотентною.
- **Інженерія** (`diagnostics.ts`): нічого не забороняє, лише пояснює. Заводські двигуни каталогу не мають отримувати фатальних діагнозів.

Каталог не описує двигуни окремо. Запис у `src/data/engines.ts` (`CatalogueEntry`) містить лише конфігурацію конструктора, порядок запалювання, заводську калібровку й текст статті, а `catalogueSpec` (`src/designer/catalogue.ts`) збирає з них той самий `EngineSpec` через `resolveDesign` і `designToSpec`. Отже, новий параметр конструктора одразу доступний і каталогу.

`Design.factory` тримає холостий хід, час набору обертів, характер і гучність реального двигуна. `editDesign` скидає його після першої інженерної зміни, далі все рахує модель. Тому каталог будується без запуску `evaluate` (`factoryInputs`), і сторінка не платить за модель на старті.

`tests/catalog-snapshot.test.ts` фіксує все, що читають 3D і звук, для кожного двигуна. Якщо він упав, відвідувачі отримають інший двигун. Оновлювати знімок можна лише тоді, коли зміна навмисна. Зміни з панелі йдуть лише через `editDesign`, бо вона знає, які залежні поля скинути.

Турбіна будується в `src/scene/turbo.ts` у реальному масштабі за `turboHp` (потужність на одну турбіну), а в рентгені її корпуси прозорі, щоб було видно колеса. Роторний двигун турбіни поки не малює.

`Stage.setModel` тримає відстань камери в межах сторінки й кадрує за найбільшим двигуном (`pageFrameScale` у `main.ts`), тому розміри можна порівнювати на око.

Звук визначає насамперед випуск: зі спільним збірником і рівними спалахами `I6` і `VR6` звучать однаково. Тому зміна компоновки в інтерфейсі йде через `withLayout`, яка ставить типовий для неї вихлоп.

Колінвал задається таблицею `throws` (кут шийки й оборот спалаху на циліндр), порядок запалювання виводиться з неї (`firingFromCrank`). Каталог нумерує циліндри по-різному, а конструктор завжди вздовж рядів, тому `throwsForFiring` у `catalogue.ts` будує таблицю з порядку запалювання.

`DesignerPage` оновлює різне з різною частотою: цифри на кожну зміну, 3D кілька разів на секунду (і лише коли зміниться `geometryKey`), звук після паузи, гучність (`measureTrim`) ще пізніше. Причина в тому, що `setConfig` у синтезі робить короткий провал звуку.

`reliability.ts` зводить міцність до навантажень від 0 до 1, і з них виходять вирок, зони обертів, знос і причина поломки. `sensitivity.ts` рахує всі твердження про вплив контролів, двічі запускаючи модель, тому текст вручну про це не пишемо. Новий контрол має давати видимий наслідок або мітку `only`, інакше впаде тест `no control is dead`.

Модель калібрується лише глобальними константами проти `tests/real-engines.ts`. Формули та їхній статус описано в `docs/engine-designer-model.md`. Поправки під окремий двигун у `physics.ts` не додаємо, тільки в заготовки `REAL_TUNE`.

Таблиця моменту `tuning.torqueTable` вже без тертя, тому `EngineSim` з нею на повному газу не додає власного опору, а її вісь нормована на `redlineRpm` специфікації.

## Як додати двигун

1. Додай запис у `CATALOGUE` (`src/data/engines.ts`): конфігурацію, `firing`, `factory` і статтю. Тести по каталогу підхоплять його автоматично.
2. Запусти `node scripts/calibrate.ts`.
3. Запусти тести: `tests/kinematics.test.ts` покаже, чи сходиться порядок запалювання з кутами рядів, а знімок треба створити для нового двигуна.

Цифру, яку не вдалося звірити з першоджерелом, познач у полі `verifyNote`: воно показується в статті.

## Як додати реальний двигун на сторінку компоновки

1. Додай запис у `ENGINE_VARIANTS` (`src/data/engine-variants.ts`): факти, джерела, `factory` і в `design` лише те, що відрізняє його від двигуна сторінки. Адреса: `#/engines/<сторінка>/<id>`. Незвірені поля перелічи в `unverified`, вони показуються в статті.
2. Запусти `node scripts/calibrate.ts`. Базові значення гучності від цього не змінюються.
3. `tests/variants.test.ts` звіряє модель із заводськими цифрами (потужність ±20%, момент −30/+35%) і вимагає, щоб двигун не був фатальним за діагнозами. Не змінюй межі, щоб пройти тест: підбери дихання, наддув або суміш. Чесний виняток описуй у `note`, як знижене стиснення KTM 1290.

Свист, скид тиску й прострели (`turboWhine`, `blowoff`, `pops` у `Design`) задавай лише за свідченнями про заводське авто, а без них лишай тихе значення. Форуми й відео здебільшого про тюнінг, тому вони не підходять. Рівень свідчень лежить у `voiceEvidence` і показується в статті. Дизель не має прострелів і скиду: у нього немає дроселя.

Вступ статті й розділи про будову й звук описують компоновку, тому на сторінці варіанта вони стоять під заголовком «Про цю компоновку загалом», а блок про сам двигун іде першим.

## Перевірка в браузері

У headless Chromium WebGL потребує прапорців `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`. На програмному рендері плавність анімації не оцінюється.

`window.__engine` дає доступ до `drive` і `stage`, а `drive.snapshot()` показує стан із аудіопотоку. Звук стартує лише після жесту користувача, тому в автотесті треба клікнути `#ignition`.

Тимчасові результати клади в `.tmp/` і `.playwright-mcp/`, обидві теки в `.gitignore`.
